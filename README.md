# 说人话，选笔记本

> 把「我平时写写代码，屏幕看着清楚点，别太沉」这种模糊的自我描述，
> 翻译成可验证的结构化约束，再筛出候选机型，最后用人话解释它为什么适合你。

## 一、这个项目解决什么问题

买笔记本时，用户能说出来的往往是**感受**（"看着清楚""背着不累""便宜点"），
而选购真正需要的是**参数**（ppi、重量、内存、显卡）。

横在中间的这道翻译，就是本项目的核心。
它不是一个"帮你搜配置的筛选表单"——删掉 AI 之后，剩下的才是一个筛选表单。

## 二、技术架构

### 三段式设计（核心）

```
用户的一句话
    ↓  ① AI 翻译（大模型结构化输出）
结构化约束 { 预算≤6000, ppi≥190, 重量≤1.5kg, 用途: 写代码 }
    ↓  ② 规则筛选（确定性引擎，AI 不参与）
候选机型 3 台
    ↓  ③ AI 解释（大模型把参数翻译成人话）
"它的屏 2.8K 14 英寸，ppi 243，你盯着看一天也不容易累"
```

**设计铁律：AI 永远不生成参数。** 所有参数来自机型库，AI 只负责解释参数对你意味着什么。
模型负责理解意图，规则负责保证结果正确——AI 在两头，规则在中间。

### 目录结构

```
src/
├── app/
│   ├── page.tsx           主界面：输入框 / 条件胶囊 / 翻译依据 / 结果卡片
│   └── layout.tsx         全局布局与元信息
├── data/
│   ├── laptops.ts         机型库（13 台真实参数，含 ppi / 重量 / 续航等）
│   └── dictionary.ts      需求词典（15 条：人话 → 参数门槛 + 展示给用户的翻译依据）
└── lib/
    └── match.ts           规则引擎：解析 / 匹配 / 排序 / 空结果自动放宽
```

### 关键设计决策

**① 预算属于用户的硬约束，程序不擅自放宽**
当条件冲突导致结果为空时，引擎会逐项放宽非预算条件（存储 → 续航 → 刷新率 → 内存 → 尺寸 → ppi → 重量），
但**永远不会动预算**。如果预算内确实没有，它不做主决定，而是给出"最接近但超预算"的机型，
标明超出多少元，把选择权交还用户。

**② 翻译过程可见、可修改**
界面不只给结果，还展示"我理解到了哪些条件"，每条都可以单独删除并立即重算。
用户能看到翻译的过程，而不是只能接受一个黑盒结论。

**③ 无 Key 也能跑通全流程**
检测不到 API Key 时自动降级为本地关键词词典解析，界面与筛选完全正常。
评委拿到项目后无需任何配置就能看到完整效果。

## 三、安装与运行

### 环境要求

- Node.js 20 或更高版本（推荐 LTS）
- 不需要数据库，不需要后端服务

### 步骤

```bash
# 1. 安装依赖
npm install

# 2. 配置环境变量（可选，不配也能跑）
cp .env.example .env.local
# 然后编辑 .env.local 填入你的 API Key

# 3. 启动
npm run dev
```

打开 http://localhost:3000 即可。

### 试试这几句话

- `预算 6000 以内，主要写代码，屏幕要看得清，最好轻一点`
- `打游戏，预算 8000 左右，屏幕要爽`
- `上课用，一天不用充电，背着不累`
- `预算 3000 以内，我要打游戏` — 看它如何不擅自改你的预算

## 四、环境变量

| 变量名 | 必填 | 说明 |
|---|---|---|
| `DEEPSEEK_API_KEY` | 否 | DeepSeek 的 API Key，留空则走本地关键词兜底 |
| `ZHIPU_API_KEY` | 否 | 智谱 GLM 的 API Key，备选模型 |

真实 Key 只存在于本地 `.env.local`，已被 `.gitignore` 排除，不会进入仓库。
